Agentic RAG 让 AI 智能体控制检索增强生成（RAG）的检索过程。面对复杂问题，智能体可以拆解任务，选择数据源，并根据已有结果决定下一次查什么。检索结束后，它会根据找到的证据生成回答。

## 先看全貌

想象你去图书馆找答案。采用固定流程的 RAG 像一位馆员，收到问题后取来一本最相关的书，再由大语言模型（LLM）阅读并作答。这个过程只检索一次，速度很快。

Agentic RAG 更像一位研究者。研究者先判断应该去哪里找，再检查找到的材料是否足以回答问题。证据不足时，可以换一个书架，或根据已有线索追查另一个问题。[AI 智能体](/posts/ai-agent/)在检索流程中承担的就是这项工作。

## 回顾 RAG

[检索增强生成（RAG）](/posts/retrieval-augmented-generation-rag/)在回答前查找相关资料，再把资料交给模型。以一次向量检索为例，系统把用户的问题转换成[嵌入向量](/posts/what-are-embeddings/)，在[向量数据库](/posts/how-does-a-vector-database-work/)中找到最相关的若干[文档片段](/posts/chunking-strategies-for-rag/)，然后把问题和片段一起交给 LLM 生成答案。

```text
用户提问 → 将问题向量化 → 向量检索（取前 k 个片段）→ LLM 生成答案
```

这条固定流程也可以增加环节。例如，[HyDE](https://outcomeschool.com/blog/how-does-hyde-work)先让模型写一份假设性答案，再用它的向量去检索相关文档。[重排序模型](/posts/how-does-a-reranker-work/)则可以在检索后重新评估候选片段的相关性，把更相关的片段排在前面。

## 回顾 AI 智能体

[AI 智能体](/posts/ai-agent/)以 LLM 为决策核心。模型根据任务和已有信息选择下一步行动，运行环境负责执行工具，再把结果交回模型。模型读到结果后，可以继续行动，也可以结束任务。

## 单次检索的局限

- **多跳问题。** 要回答「2023 年收购 Acme 的公司当年第四季度营收是多少」，通常得先查到收购方，再用公司名称查财报。第一次查询的结果决定第二次查什么。
- **查询有歧义。** 用户问「新政策怎么样了？」时，如果缺少上下文，直接检索可能找错政策。系统可以先根据对话明确政策，也可以请用户补充信息。
- **数据分散在多个来源。** 结构化财务数据可能在 SQL 数据库里，内部文件可通过向量检索查询，最新消息可能要上网搜索。固定使用一个来源会限制能找到的证据。
- **检索结果质量不稳。** 排在前面的片段也可能答非所问。直接把这些片段交给模型，容易得到缺少依据的答案。

## 什么是 Agentic RAG

Agentic RAG 在检索流程中加入可反复执行的决策步骤。智能体先判断是否需要查资料，再选择工具、组织查询、检查结果，并决定怎样继续。如果已有证据不足，可以改写查询、换一个来源，或结合多个来源。证据足够时，可以结束检索并整理答案。

## 检索循环

```text
用户提问
  ↓
智能体判断是否需要检索
  ├─ 无需检索 → 直接回答
  └─ 需要检索 → 选择工具并构造查询
                    ↓
               工具返回结果
                    ↓
               智能体检查证据
                    ├─ 证据足够 → 生成最终回答
                    └─ 证据不足 → 调整查询或更换来源，再检索
```

运行环境需要给循环设定停止条件，例如限制最大检索轮数。达到上限时，如果证据仍然不足，答案应说明这一点。

## 三个组成部分

1. **智能体。** LLM 读取用户问题和当前线索，决定下一步要查什么，并评估工具返回的材料。
2. **检索工具。** [向量检索](https://outcomeschool.com/blog/how-does-approximate-nearest-neighbor-ann-search-work)适合按语义查找文档，关键词检索适合匹配术语，SQL 适合查询结构化数据，网页搜索适合查公开信息，知识图谱适合查询实体之间的关系。
3. **运行循环。** 运行环境接收模型给出的工具名和参数，执行调用，再把结果交回模型。它还会保存本轮已尝试的操作及结果。这个临时工作记录也叫 `scratchpad`，属于[智能体记忆](/posts/ai-agent-memory/)的一种。模型可以借此利用已有线索，避免重复搜索。

## 示例　先找收购方，再查营收

还是以 Acme 为例。用户想知道在 2023 年收购 Acme 的公司，当年第四季度的营收是多少。下面用虚构公司展示检索过程。

1. 智能体识别出问题分两步，首先需要确定收购方。
2. 它选择网页搜索，查询「2023 年收购 Acme 的公司」。
3. 搜索结果指向 Globex，智能体据此确定下一步要查 Globex 的 2023 年第四季度营收。
4. 它选择在内部财务报告中做向量检索，查询「Globex 2023 年第四季度营收」。
5. 工具返回季度财报片段，智能体检查片段是否包含所需数字，然后依据材料回答。

实际的搜索结果通常包含多条摘要，智能体需要先判断哪些结果与问题相关。同一轮也可以组合多个来源，例如用向量库查概念定义，再用网页搜索补充最新消息。检索工具可以按数据结构选用。例如，[Vectorless RAG](/posts/vectorless-rag/)可以利用文档的目录和章节结构查找相关段落。

## 常见模式

- **ReAct 式 RAG。** 智能体在[推理、行动、观察的循环](/posts/ai-agent-loop/)中推进任务。它先确定该查什么，再执行检索，最后根据结果决定下一步。上面的 Acme 示例就采用这种思路。[ReAct 智能体](/posts/react-agent/)
- **Self-RAG。** 模型判断是否需要检索，并检查材料是否与问题相关、生成的内容是否有依据。评估结果可以用来取舍检索片段和候选答案。
- **Corrective RAG（CRAG）。** 系统先评估检索结果的质量。结果不理想时触发补救流程，例如改用网页搜索获取资料。

## 固定流程 RAG 与 Agentic RAG 的比较

这里把一次检索、一次生成的基础流程作为对照。实际系统也可以在固定流程中加入查询改写、重排序或结果过滤。

| 维度 | 固定流程 RAG | Agentic RAG |
| --- | --- | --- |
| 执行流程 | 预先定义 | 按结果动态调整 |
| 检索轮数 | 一轮 | 按需检索，可运行多轮 |
| 工具和数据源 | 预先选定 | 按问题选择，可组合多个来源 |
| 查询改写 | 可按预设规则处理 | 可结合中间结果重新组织查询 |
| 结果评估 | 可用固定规则或重排序 | 可评估证据是否足够，并决定是否重试 |
| 多跳问题 | 容易缺少后续线索 | 可分步检索并传递线索 |
| 延迟、成本和实现复杂度 | 通常较低 | 通常随检索轮数和工具数量增加 |

## 什么时候用 Agentic RAG

以下任务更可能从 Agentic RAG 受益。

- 问题有多个相互依赖的步骤，后一步需要用到前一步找到的信息。
- 数据分散在向量库、SQL 数据库、网页或文件中，需要按问题选择来源。
- 用户的问题比较模糊，需要补足上下文或[改写查询](/posts/how-do-query-rewriting-and-multi-query-retrieval-work/)后再检索。
- 证据质量比响应速度更重要，例如研究和资料核查。
- 同一个入口既要回答需要查资料的问题，也要处理问候或闲聊。

如果问题直接、数据集中，而且响应速度和调用成本很重要，固定流程 RAG 通常就够用。

## 局限和代价

- **延迟和成本更高。** 多轮检索通常伴随多次模型调用。工具返回的数据也要进入后续上下文，增加 token 消耗。
- **调试更难。** 同一个问题在不同运行中可能走不同路径。检查问题时，需要看到智能体选择了哪些查询、工具和来源。
- **循环可能持续太久。** 系统可以根据模型的完成信号、证据是否充分或最大步数来结束循环。即使模型自认为有把握，也要检查材料是否支持答案。
- **系统更复杂。** 工具接口、提示词、[评估流程](/posts/ai-agent-evaluation/)和停止条件都需要设计与维护。

## 小结

固定流程 RAG 按预设步骤检索和生成。Agentic RAG 由智能体、检索工具和运行循环配合，能把复杂问题拆成多个查询，并根据证据调整检索路径。这种灵活性适合多跳和多来源任务，也会增加耗时、调用开销和维护成本。

## 常见问题

### Agentic RAG 总是更合适吗？

问题直接、资料集中时，固定流程 RAG 通常更容易实现，响应也更快。需要分步核查或跨来源取证时，可以用 Agentic RAG。

### LLM 怎样调用搜索工具？

模型输出工具名和参数，由运行环境执行调用，并把查询结果交回模型。

### 智能体怎么判断何时停止搜索？

常见的停止条件包括模型发出完成信号、证据已足以回答问题，或达到最大步数。限制步数可以避免智能体反复重试。

### 哪些问题可以直接回答？

问候和闲聊通常可以直接回答。是否查资料由智能体根据任务决定。

### Self-RAG 和 Corrective RAG 有什么区别？

Self-RAG 侧重判断检索材料是否相关，以及材料是否支持生成的内容。Corrective RAG 侧重在检索结果不理想时采取补救措施，例如切换到网页搜索。
