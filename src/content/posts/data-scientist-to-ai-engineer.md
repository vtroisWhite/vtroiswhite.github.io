数据科学家转型为 AI 工程师，可以继续发挥 Python、统计和评估能力，同时补上软件工程、API、部署、智能体和使用编程智能体开发的习惯。

## AI 工程师做什么？

AI 工程师利用现成的模型做产品，工作涉及提示词、检索增强生成（RAG）、智能体、评估和部署。以企业客服为例，工程师要从内部文档中找出相关片段，把资料交给大语言模型生成回答，测量回答质量，并把功能部署成应用能调用的服务。

在原文给出的典型分工中，数据科学家清洗数据、发现规律、训练和分析模型，产出可能是 Notebook、报告或模型文件。AI 工程师通常从接入现成模型开始，交付包含它的可用系统。

## 数据科学经验中哪些可以迁移？

- **Python。** 已有编程基础可以直接用于模型 SDK、检索和后端代码，主要变化是库和项目结构。
- **统计。** 比较两个版本时，需要考虑样本量和随机波动，区分真实改进与偶然变化。
- **评估。** 测试集、精确率、召回率、基线和指标设计，都能用于大语言模型评估。
- **模型直觉。** 对训练、过拟合和未见数据的理解有助于排查模型为何出错。
- **数据清洗。** RAG 的效果取决于输入文档质量。处理脏数据、缺失内容和异常记录的经验可以用在文档分块与索引阶段。

## 还需要补上什么？

- **软件工程。** 用版本控制、清晰结构、测试、异常处理和日志，让代码能被他人阅读、运行和维护。
- **API 和服务。** 设计请求、响应及错误契约，给其他系统提供可调用的接口。
- **部署。** 掌握容器、环境变量、密钥和云端托管，把服务从本地搬到运行环境。
- **智能体。** 模型决定调用什么工具，应用负责执行并反馈。还要处理状态、记忆和护栏。
- **生产可靠性。** 模型 API 可能延迟、失败或返回错误格式。服务需有超时、重试、回退和监控。
- **与编程智能体协作。** 清楚地交代任务，审核和测试生成的代码，并亲自做系统设计。

## 建议的学习顺序

1. **把 Notebook 变成项目。** 用 Claude Code 等编程智能体把旧 Notebook 拆成函数、目录和测试，逐个文件审查。
2. **调用模型 API。** 写一个收发提示词的脚本，理解系统提示词、用户消息、温度、最大词元数和结构化 JSON 输出。
3. **搭建 RAG。** 学习嵌入向量、向量检索和检索结果的注入方式。让编程智能体搭起流程，把精力放在分块方案和检索质量上。
4. **建立评估集。** 准备带预期答案的问题，让编程智能体编写评估运行器，自己选指标、估算样本量并解释分数变化。
5. **封装并部署服务。** 设计接口、加入错误处理和日志，打包成容器并部署到云端。
6. **加入智能体。** 让模型使用搜索和计算器等工具，逐行审查执行循环，为工具加护栏，为多步任务加评估。
7. **补上生产可靠性。** 增加重试、超时、回退、延迟和单次请求成本监控，主动模拟模型 API 故障来检查服务行为。

## 用编程智能体做哪些项目？

| 项目 | 要验证什么 |
| --- | --- |
| 部署一套文档问答服务 | 在问题集上的检索准确性、答案质量、单次请求延迟 |
| 给现有 AI 摘要等功能建立评估套件 | 对照三种提示词，观察分数差异是否有统计意义 |
| 实现搜索、计算并生成回答的多步智能体 | 任务完成率、平均工具调用次数、工具失败时的行为 |

每个项目都应在 README 说明构建目标、评估方法、结果和下一步改进点。

## 如何展示转型成果？

从擅长的评估讲起，说明如何把数据科学的严谨方法用于大语言模型产品。展示有运行方式、测试和评估数据的项目。面试时说清如何指挥编程智能体、复核它的代码、发现并处理问题。如果部署是转型后学到的，直接说明并指向实际部署的项目。简历可在符合实际经验的地方使用 RAG、评估、工具调用、智能体和部署等术语。

## 常见问题

### 两类岗位的主要区别是什么？

数据科学家的典型产出是数据分析、模型和实验结果。AI 工程师通常利用已有模型和外部数据、工具，交付可运行的产品。

### 一个 Notebook 能展示 AI 工程能力吗？

项目还需要展示可调用的服务、测试、运行方式和可核查的评估指标。

### 数据科学家可以先学什么？

先用编程智能体把旧 Notebook 改造成带目录、函数和测试的 Python 项目，并亲自审查产物。

### 数据科学家的评估能力有什么价值？

熟悉测试集、指标、基线和统计波动，有助于确定输出是否可靠，以及分数变化是否代表真实的产品改进。
