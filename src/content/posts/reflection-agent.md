反思智能体先生成草稿，再评审草稿，利用反馈修订，直到达到质量要求。它是一种[AI 智能体](/posts/ai-agent/)模式，适合写作、方案等难以直接用规则判定好坏的任务。有确定性验收手段时，可以把实际结果纳入[完成标准](/posts/ai-is-only-as-good-as-our-definition-of-done/)。

## 反思循环有哪些部分

```text
+--------------------------------------------------------+
|                    The Agent Loop                      |
|                                                        |
|   User Task                                            |
|       |                                                |
|       v                                                |
|   +-----------+         +--------+                     |
|   | Generator |  ---->  | Critic |                     |
|   +-----------+         +--------+                     |
|       ^                     |                          |
|       |                     v                          |
|       |               +------------+                   |
|       +-- (revise) -- | Stop Check | -> Final Output   |
|                       +------------+                   |
+--------------------------------------------------------+
```

- **生成器**根据任务写第一稿，以后根据上一稿和评审意见修订。
- **评审器**指出缺失、错误与可改进之处，体现了[用大模型当评审](/posts/llm-as-a-judge/)的思路。可以同一模型分别扮演两个角色，也可以使用不同模型。
- **工具**可辅助事实检查、核对引用或运行测试。纯文本评审也能发现一部分问题。
- **[记忆](/posts/ai-agent-memory/)** 保存原任务、草稿、评语和轮数。长任务可保留最新稿和反馈，对更早记录做摘要。
- **停止检查**根据评审、轮数和质量变化决定是否结束。设置退出属于[循环工程](/posts/what-is-loop-engineering/)。

## 生成、评审和修订

先把第一稿存入记忆，评审器按标准输出可执行的反馈。草稿达标或达到轮数上限时交付，其他情况下用反馈再写一版。每轮只修订需要改的部分，同时保留可回退的旧稿。[智能体循环](/posts/ai-agent-loop/)控制重复执行，这几步也能用[图工程](/posts/what-is-graph-engineering/)的节点与边表达。

```text
+----------+      +----------+      +-------+
| Generate | ---> | Critique | ---> | Stop? | ---> [yes] ---> Final Output
+----------+      +----------+      +-------+
                       ^                |
                       |                v [no]
                       |           +--------+
                       +---<-------| Revise |
                                   +--------+
```

## 一次文案修订

原文让智能体为办公用无线鼠标写产品说明。首稿说它适合办公、能无线连接且握感舒适，表述很笼统。评审指出没有具体特性、没有说清对用户的好处，建议举出静音点击、连接方式和续航等细节。

修订稿把卖点和安静办公、会议等场景结合起来，还写入了 **18 个月续航**。这个数字没有出现在初始材料中，是生成器为满足“多写具体数字”的评语而虚构的。评审器随后放行，说明文本看起来更完整，事实仍需用规格表或其他可靠证据核验。

## 何时选用反思

| 方面 | ReAct | 反思 |
| --- | --- | --- |
| 每轮的目标 | 调工具获取信息或行动 | 根据评语改善草稿 |
| 主要变化 | 行动与观察 | 草稿与评语 |
| 工具 | 负责与外界交互 | 可选，用来验证评审或事实 |
| 退出条件 | 信息足以回答或任务完成 | 草稿达到要求或轮数耗尽 |
| 成本来源 | 模型和工具调用次数 | 生成与评审的轮数 |

[ReAct](/posts/react-agent/)适合查资料、操作外部系统。[规划与执行](/posts/plan-and-execute-agent/)可以将反思放入某个交付步骤，[Agentic RAG](/posts/agentic-rag/)也可用评审检查答案是否受证据支持。写作和代码审阅通常值得修订，[实时语音助手](https://outcomeschool.com/blog/design-a-real-time-voice-ai-agent)等低延迟场景更重视首轮速度。

## 常见故障与处理

- **评语只会赞美或过于笼统**。用具名维度检查草稿，要求指出具体句子、缺漏和可执行的修改。
- **新稿质量下降**。对照旧稿检查修改是否解决问题，必要时回退。
- **循环不停**。限制轮数。连续两轮反馈重复、没有实质进展时结束。原文举例，两到三轮常能满足需求。
- **成本快速增加**。五轮评审和修订大约需要一次初稿生成加十次调用。评审目标明确时可考虑[小语言模型](https://outcomeschool.com/blog/small-language-models-slms)，简单任务可直接使用首稿。
- **逐轮偏离目标**。每次评审都带上原任务，先判断结果是否满足要求。
- **评审诱发幻觉**。用工具核验事实、测量值和引文。缺少来源时标出待确认项。
