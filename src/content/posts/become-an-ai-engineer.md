成为 AI 工程师，可以从用现成模型做出一个可用的产品开始。先学会调用模型，再把业务资料和工具接进来，最后用评估判断功能是否值得上线。下面按这个顺序展开，并用三个项目检验学习成果。

## AI 工程师做什么

假设公司要做一个能回答产品问题、查询订单的客服助手。大语言模型（LLM）可以理解用户的问题，但公司手册和订单数据需要由应用提供。AI 工程师负责找出相关手册、接入订单查询工具、检查回答是否准确，再把整套系统部署给客户使用。

日常工作包括编写提示词、搭建检索增强生成（RAG）流程、实现工具调用循环、设计评估，以及管理线上系统的延迟、成本和安全性。机器学习工程师通常更多参与模型训练和调优，AI 应用工程的重点是把模型接入业务并保证运行质量。

## 开始前要掌握什么

- **一门编程语言。** Python 的 AI 库和示例很多，适合起步。用 Claude Code 等编程智能体协作时，自己要能读懂生成的代码，找出问题并验证修复。
- **Web 服务基础。** 理解请求、响应和 API，能读懂接口参数和错误信息。
- **常见数据结构。** 能处理列表、表格、键值对和 JSON，知道如何把模型输出转换成程序可用的数据。
- **实际使用过大语言模型。** 试过哪些问题答得好，哪些会漏掉限制或编造事实，后面做测试就有了参照。

做应用时，可以把数学和训练原理放到需要它们的阶段再深入。入门优先跑通模型调用和最小业务流程。

## 七步学习路线

1. **理解大语言模型的基本原理。** 文本会被拆成词元（token），模型根据已有内容预测接下来的词元。上下文窗口限制它一次能处理的内容，温度会影响采样的随机性。模型可以生成流畅的文本，也可能给出看似合理的错误答案。
2. **调用模型 API。** 写一段 Python 脚本，把提示词发给模型并输出回答。改几次输入，观察结果。然后试试结构化输出，例如 `{"answer":"billing","confidence":"high"}`，在程序里校验返回的 JSON。再练习流式响应和错误处理。
3. **设计提示词。** 在系统提示里写清角色和规则，在用户消息里提交当前问题。用示例展示希望看到的答案，规定输出格式和信息不足时的处理方式。原文建议至少用 20 条不同输入试跑，观察改写后哪些回答变好、哪些变差。
4. **搭建 RAG。** 把文档拆成片段，转换成嵌入向量并存入向量数据库。用户提问时，检索相关片段，再把片段和问题交给模型。用真实问题检查正确材料有没有被找回来，再检查回答有没有用对材料。
5. **实现智能体。** 给模型提供 `search_orders`、`create_ticket` 等工具的说明和参数结构。模型提出工具请求，应用校验参数、执行工具，再把结果返回给模型。给循环设定步数上限和结束条件，避免反复调用。
6. **建立评估。** 收集有预期结果的测试样例，改提示词、分块大小或模型后，用同一批样例重跑并比较结果。开放式回答可以让另一个模型按明确标准评分，再抽样人工核对。
7. **部署和控制成本。** 通过 API 提供服务，记录调用情况，衡量响应延迟和词元用量。能复用的结果可以缓存，简单任务可交给小模型，复杂任务再交给能力更强的模型。主模型不可用时，可以切换到预设的备用方案。

用编程智能体练习这些步骤时，先说清任务和验收条件，再审查生成的代码，用测试结果判断它是否符合要求。

## 三个练手项目

### 1. 给自己的文档做问答

挑一组熟悉的资料，例如产品手册或课程笔记。实现分块、嵌入、向量存储、检索和回答生成的完整流程。用 50 道题评估相关片段进入检索结果的比例，以及最终答案的正确率。比较两种分块大小，记录它们各自在哪类问题上表现更好。

### 2. 给客服智能体接入工具

用小型模拟数据库实现查订单、查退货政策和建工单。给工具调用加参数校验和步骤限制。记录任务完成率、平均执行步数，并观察用户提出业务范围之外的问题时，系统是否按预期处理。

### 3. 为前两个项目之一搭建评估脚本

让脚本运行整套评估样例，汇总得分，并列出相较上一次运行发生变化的回答。对开放式问题，可以加上模型评分，再人工抽查一部分，看看评分是否符合标准。

每个项目的 README 都应说明它解决什么问题，用图展示系统结构，写明启动步骤，并用表格列出评估结果。可以另开一节记录失败案例和相应改动。

## 怎样展示作品

- **公开能分享的项目。** 把代码、启动步骤和评估方法放进 GitHub 仓库，方便别人复现。
- **录一段两到三分钟的演示。** 展示一次成功、一次失败，并讲清楚接下来准备怎么改。
- **写一篇短文解释一个决定。** 例如为什么选用某种分块大小，有哪些测试结果支持这个选择。
- **列出可比较的数据。** 原文举例，可以用一张表展示同一评估集上的准确率怎样从 62% 提高到 81%。

## 怎样申请岗位

招聘信息可能使用 AI Engineer、Generative AI Engineer、LLM Engineer 或 AI Agent Engineer 等名称。可以把这些名称都作为搜索关键词，再按职责判断是否匹配。

读职位描述时，把要求映射到项目。RAG 对应文档问答，工具调用对应客服智能体，评估对应评估脚本。简历先写项目做了什么，再写验证结果。例如「为 400 页手册搭建 RAG 问答，在 50 道评估题上的检索命中率为 81%」。这里的数字只是原文用来说明写法的示例。

面试可能包括实操、系统设计和工程取舍。实操时，说明如何使用编程智能体、怎样审查代码和验证结果。设计时，从业务需求讲到提示词、检索、工具、评估和成本。讨论取舍时，可以说明哪些请求值得用更强的模型，哪些交给小模型就够用。

如果已经是软件工程师，也可以在现有产品里找一个适合用 LLM 改善的功能。从最小可用版本做起，建立评估，再验证它在线上是否达到预期。

## 常见问题

### 学哪门语言更方便？

Python 有较多 AI 库和示例。比记住每个库的用法更重要的是能读懂代码、运行测试并排查错误。

### 生成式 AI 工程师和 AI 工程师是同一种岗位吗？

两种名称常用于相近的岗位。团队分工会有差异，投递前可以核对职位描述里的业务目标、模型职责和交付要求。

### 面试会考什么？

原文列举了三类题目，分别是实现小功能并解释验证过程，设计一个 AI 功能，以及讨论质量、成本和延迟之间的取舍。

### 软件工程师从哪里开始最直接？

可以先在熟悉的产品中挑一个具体功能，做出可运行的版本，并用实际样例评估。上线后的效果和取舍能帮助面试官理解你在项目中的工作。
