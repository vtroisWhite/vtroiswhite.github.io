软件工程师负责设计、构建和验证应用、服务与工具。AI 工程师也做这些工作，并把现有模型连接到数据、工具和用户。两者都可以使用编程智能体编写代码，由工程师审查和验证。模型输出具有概率性，这给 AI 工程师增加了一套评估工作。

## 用同一个外卖应用来比较

软件工程师可以负责登录、购物车、支付、订单追踪及其背后的数据库。给定相同输入和状态，购物车应当得到相同的总价。两个价格均为 100 的商品，可以用确定的断言来测。

```python
def test_cart_total():
    cart = Cart()
    cart.add(item_price=100)
    cart.add(item_price=100)
    assert cart.total() == 200
```

AI 工程师可以负责外卖客服助手。用户说“订单送晚了，饭也凉了”，助手需要识别投诉、查询订单、核对退款政策并给出答复。意思相同的回复可以有多种写法，逐字比对其中一句会把合理的回复判错。一个礼貌的句子也可能包含错误的退款决定。

```python
def test_support_reply():
    reply = assistant.reply("订单送晚了，饭也凉了。")
    assert reply == "很抱歉送餐延误，我们已为您退款。"
```

这个断言只校验字面内容。客服评估更需要判断退款动作、事实依据和措辞是否满足要求。模型服务商更新模型也可能改变结果，即使应用代码没有变动。

## AI 工程师要多负责哪些工作

| 工作 | 在客服助手里的做法 |
| --- | --- |
| 评估 | 收集 200 条投诉，标注正确处置方式。答对 180 条就是 90%，后续修改用同一套样本比较 |
| 提示词 | 将模型的任务指令纳入版本管理，用评估数据测量改写前后的差异 |
| 检索 | 在回答前拿到正确的订单信息和退款政策，用 RAG 将材料交给模型 |
| 智能体 | 约定可用工具、调用参数和终止条件。模型提出查询某个订单，应用代码执行查询 |
| 成本和延迟 | 统计输入输出词元、复用重复计算，为简单步骤选择够用的模型 |

## 调试方法有什么变化

购物车总价错误时，可以从输入、程序状态和实现里追查计算错误。客服助手给出错误事实时，还要检查检索资料、提示词、模型版本和实际请求。常规单元测试和集成测试仍然适用于程序逻辑，模型质量则要用一组代表性任务和评分标准来衡量。

## 选择哪种工作

喜欢具有明确输出的业务功能，可以继续深耕软件工程。对检索、模型行为和质量评估感兴趣，可以在原有的系统设计、编码和审查技能上补足这五项工作。原文建议用一个小型模型应用练习完整过程，从实现到建立评估集，再用分数衡量改进。
